## 1. Задание 6.1. Исследование DOM и распространения события

**Страница экспериментов:** `examples/dom-events.html`

| № | Прогноз до запуска | Фактический результат | Причина |
|---|---|---|---|
| 1 | `querySelector("#missing-element")` вернёт `null`. `querySelectorAll(".nonexistent")` вернёт пустой `NodeList` (длина 0). У `null` нельзя читать свойства — `missing.textContent` вызовет `TypeError`. У пустой коллекции можно читать `length` и индексы — `empty[0]` вернёт `undefined`. | `missing` → `null`. `empty.length` → `0`. `missing.textContent` → `TypeError: Cannot read properties of null (reading 'textContent')`. `empty[0]` → `undefined`. | `querySelector` возвращает `null`, если совпадений нет. `querySelectorAll` всегда возвращает `NodeList` (даже пустой). Чтение свойства у `null` — ошибка, у коллекции — безопасно. |
| 2 | `dataset.taskId` вернёт **строку** (тип `"string"`), например `"23"`. После `Number(raw)` получим **число** `23` (тип `"number"`). Если бы значение содержало буквы, `Number()` вернул бы `NaN`. | `raw = "23"`, `typeof raw = "string"`. `num = 23`, `typeof num = "number"`. `Number.isSafeInteger(num)` → `true`. | Атрибуты `data-*` всегда хранятся в `dataset` как строки. `Number()` явно преобразует строку в число или возвращает `NaN`, если строка не является числом. |
| 3 | Длина сохранённой коллекции `initialItems.length` **не изменится**. А новый `document.querySelectorAll(".item").length` **увеличится** (например, с 2 до 4). | `initialItems.length` → **не изменилось** (например, `1`). `document.querySelectorAll(".item").length` → **увеличилось** до нового значения. | `querySelectorAll` возвращает **статическую** коллекцию — снимок DOM на момент вызова. Добавление новых элементов не обновляет старую ссылку. Для актуального состояния нужен новый запрос. |
| 4 | В заголовке отобразится **текст с угловыми скобками** — буквально `<strong>Новый заголовок</strong>`. HTML-элемент `<strong>` **не создастся**. Проверка `children.length` вернёт `0`. | В заголовке видна строка `<strong>Новый заголовок</strong>` как обычный текст. `document.querySelector("h1").children.length` → `0`. | Использовано свойство `textContent`, которое вставляет содержимое как **текст**, а не как HTML. Чтобы создавался элемент, нужно было бы использовать `innerHTML`. |
| 5 | В журнале событий будут три фазы: **1 (захват) → 2 (цель) → 3 (всплытие)**. `event.target` — вложенный `<span>`. `event.currentTarget` — **кнопка**. Обработчик кнопки вызовется благодаря **всплытию**. | В журнале последовательно появились фазы 1, 2, 3. На фазе 2: `event.target` → `<span>`, `event.currentTarget` → `<button>`. На фазе 3 обработчик кнопки выполнился. | Событие сначала проходит фазу захвата (1) от корня до цели, потом фазу цели (2) на самом вложенном элементе, потом фазу всплытия (3) обратно вверх. Обработчик кнопки вызовется на всплытии, поэтому `target` — `<span>`, а `currentTarget` — `<button>`. |

**Критерий готовности выполнен:** заполнены пять экспериментов, объяснено, почему обработчик контейнера получает нажатие на вложенный элемент (из-за **всплытия событий**).
