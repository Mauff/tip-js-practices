## Организация кода

* `task-service.js` — чистая бизнес-логика (создание, обновление, удаление, расчёты). Не зависит от DOM и хранилища.
* `form-validation.js` — чистая валидация черновика формы. Возвращает объект с ошибками, не меняет данные.
* `task-storage.js` — работа с `localStorage`. Инкапсулирует JSON-парсинг и `try/catch`.
* `task-view.js` — только создание DOM-элементов и отрисовка. Не меняет данные.
* `main.js` — связывает всё: обрабатывает события, вызывает сервисы, хранилище и перерисовку.

Функции хранения получают `storage` аргументом, чтобы их можно было протестировать с имитацией (mock) без реального `localStorage`. Данные из JSON проверяются до использования (`isValidTaskList`), потому что `JSON.parse` гарантирует только синтаксис, но не корректность структуры.

## Вывод

В ходе работы реализовано приложение с формами создания и редактирования, двумя уровнями валидации (нативной HTML и прикладной) и сохранением состояния в `localStorage`.

**Различие проверок:**
1. **Нативная проверка HTML** (`required`, `maxlength`, `min`) — быстро проверяет структуру ввода, но не знает правил модели (например, уникальности id).
2. **Прикладная валидация** (`validateTaskDraft`) — проверяет бизнес-правила (уникальность id, `trim` названия, допустимый приоритет) и возвращает понятные ошибки для полей.
3. **Проверка данных из хранилища** (`isValidTaskList`) — нужна после `JSON.parse`, так как JSON гарантирует только синтаксис, но не корректность структуры (версию, уникальность id, типы полей). При ошибке приложение не падает, а загружает исходный набор.
