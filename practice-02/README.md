## 4. Модель данных и функции

**Поля задачи:**

* **id** — положительное безопасное целое (`Number.isSafeInteger(id)` и `id > 0`).
* **title** — строка длиной от 1 до 100 символов после `trim()`.
* **completed** — логическое значение; при создании всегда `false`.
* **priority** — одно из `"low"`, `"medium"`, `"high"`; по умолчанию `"medium"`.

**Правила валидации:** при успехе функции возвращают `{ ok: true, ... }`; при ошибке — `{ ok: false, error: "..." }`. Строковый id не преобразуется в число, `null` не заменяется значением по умолчанию.

**Назначение файлов:**

* `src/data.js` — исходные данные (`demoTasks`, `variantTasks`, `variantNumber`).
* `src/task-service.js` — 9 прикладных функций.
* `src/main.js` — демонстрационный сценарий.
* `src/task-extra.js` — дополнительное задание (поиск по названию).
* `checks.js` — проверочные сценарии.
* `examples/functions-and-references.js` — учебные эксперименты.

**Почему id не равен индексу:** идентификатор — уникальный номер задачи, не меняется при удалении или добавлении других элементов. Индекс — позиция в массиве, которая зависит от количества элементов. Поиск по id через `find` надёжнее, чем `tasks[id]`.

**Почему getTaskStats возвращает число, а не строку с процентом:** число удобнее для дальнейших вычислений и форматирования. Строка с процентом создаётся только при выводе в `main.js` с помощью `toFixed(1)`.

**Какие объекты копируются при изменении задачи:** при изменении задачи создаётся новый объект только для изменяемой записи (`{ ...task, ...updates }`). Остальные объекты в массиве переиспользуются. Сам массив всегда создаётся новый (`map`, `filter`, `[...tasks]`).
